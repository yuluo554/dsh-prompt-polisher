# 03-模块详设

## 3.1 npm 包形（目标 M1 落定）

```
dsh-prompt-polisher/
├─ package.json            # dsh.bundle.patch + dsh.client + exports ./client；@deepseek-ai/* 精确 pin
├─ cordis.patch.yml        # ① 本插件 insert 行 ② workflow-ptc disabled:false（M2 起）
├─ src/
│  ├─ index.ts             # host 半: export default apply(ctx)
│  ├─ rpc.ts               # /api/prompt-polisher/optimize 处理器
│  ├─ optimize/            # 模板渲染、通路分派、输出清洗
│  ├─ client/              # client 半源码（按钮组件、状态条、RPC 客户端、locale hook）
│  └─ ambient.d.ts         # 席位类型 import type {} 声明合并挂载
├─ scripts/build.mjs       # esbuild: host tsc + client cjs bundle（ModuleLoader banner/footer）+ require 白名单扫描门
├─ locale/zh.json en.json
├─ lib/                    # 构建产物（npm files 只含此目录 + patch + locale）
└─ test/                   # node:test 三层
```

## 3.2 host 半

- `apply(ctx)`：注册 RPC `ctx.connection.fetch.register({ path: '/api/prompt-polisher/optimize', methods: ['POST'], requestBody: 'buffered', fetch })`（dsh-plugin-dev §5 模式；浏览器裸 fetch，cookie 由 carrier 处理）。
- 请求：`{ draft: string, style: string, source?: 'button' }`；响应：`{ ok: true, optimized: string, style, modelVia: 'session'|'api' } | { ok: false, error: code }`。错误码：`EMPTY_DRAFT / TOO_LONG / UPSTREAM_FAILED / PARSE_FAILED / CANCELLED / BAD_STYLE`。
- 优化管线（host 侧纯函数，可离线单测）：
  1. 校验（非空、≤上限如 8000 字符）；
  2. 模板渲染：`renderTemplate(styleTemplate, { draft, locale })`；
  3. 通路分派：配置了独立 API → 直连 fetch；否则 workflow 引擎；
  4. 输出清洗：剥 ``` 围栏、去首尾成对引号、截断上限、非空校验；
  5. 返回 meta（耗时、通路、style）。
- 引擎 script 细节（R5 对策）：script 体固定，草稿经 `args` 注入（`agent(args.prompt, ...)`），全文不拼接进 script 字面量；script 字符串在测试里用含反引号/`${}`/中文的 fixtures 验证。
- 引擎调用：`meta` 必填合法（name: 'prompt-polisher'，description 非空）；单 agent；`run.result.stopReason !== 'completed'` → UPSTREAM_FAILED/CANCELLED。

## 3.3 client 半

- 组件一：**优化按钮**（注册 `conversation.input.right`，list 席位，id 'prompt-polisher.button'）
  - 自绘 SVG 图标（"笔尖+双星火"方向，区别于 WorkBuddy 单魔法棒；M4 定稿）；tooltip locale 文案。
  - 状态机：`idle → optimizing(转圈, 禁点) → done(短暂高亮) / error`。
  - 点击：`const draft = useInput().draft` → POST RPC → 成功：先 `inputActions.captureInsertion()`/重读比对（R6），再 `inputActions.setDraft(optimized)`，并广播状态条显示。
  - 禁用条件：`draft.trim().length < 8`；`occurrences.length > 0`（R1，tooltip 说明）；`phase !== 'plain'`（claimed/submitting 中）。
- 组件二：**状态条**（注册 `conversation.composer.dock`，list）
  - 显示"已用〈风格〉优化 · [还原] [换风格↻]"；点还原 → `setDraft(original)`；原文与优化结果保存在插件内存态（per-session Map，会话切换即清）。
  - 无优化记录时渲染 null（不占空间）。
- 组件三（M3）：**风格菜单**：按钮旁下拉（或按钮长按/右键），列预设风格 + "打开设置"；选择记忆到 localStorage。
- 竞态语义（R6 定稿）：发起优化时记 `draftRev0`；返回后若 `useInput().draftRev !== draftRev0 && draft !== original` → 状态条提示"草稿已变动，仍要替换？[替换] [放弃]"，不静默覆盖。
- bundle 构建：esbuild `format:'cjs'` + banner `window.__ModuleLoader__.load({id, factory:(require)=>{...}})`；新浏览器依赖三处同步（package.json `dsh.client.external` + 构建种子表 + ambient.d.ts）；构建后 require 白名单扫描（purity gate）。

## 3.4 风格模板（M2 两个起步，M3 可自定义）

- `concise`（精炼明确）：保持原意与语言，消歧义、补必要上下文、去冗余，不大幅扩写。
- `structured`（结构化增强）：重写为 角色/任务/约束/输出格式 四段式完整提示词（中文草稿出中文模板骨架，英文出英文）。
- 模板 = system prompt（角色+要求+只输出改写文本）+ user（草稿原文）。模板以 locale JSON + 内置常量存放；自定义模板（FR10）= 用户配置覆盖内置。
- 输出约束写死进模板：不解释、不包裹、不改语言、保留草稿中的 @/ 引用记号原样（R1 配套，即使 M2 禁用含 chips 优化也先写进模板）。

## 3.5 图标与 UI 细节（对标 WorkBuddy）

- 位置：composer 工具行右侧区（`input.right`），视觉上是 16~18px 线性图标按钮，hover 有浅底色，与官方工具行控件同密度。
- 图标自绘：方向"笔尖+星火"（polish/打磨意象），上线前画 2~3 个候选 SVG 由用户挑选。
- 交互：单击=用当前默认风格优化；M3 加下拉箭头或长按出风格菜单（WorkBuddy 无此菜单，属我们的扩展）。
