# 04-数据与测试计划

## 测试三层（全离线，node:test，模型 API 永不进 CI）

1. **纯函数层**：模板渲染、输出清洗（围栏/引号/超长/空输出）、错误码映射、请求校验——普通单测。
2. **通路层**：
   - 通路 A：真实 `dsh-workflow-ptc` 引擎 + 桩 ptcRuntime/subagents/sandboxPolicy（dsh-plugin-dev §6 桩形态：run 带 `id` 字段、手动 new 引擎传全量 config）——验证 script 合法、meta 校验、草稿经 args 注入不破 script、取消/失败映射错误码。桩子代理返回 fixtures 文本（含"带围栏的输出"用例验证清洗）。
   - 通路 B（M3）：stub fetch（注入 base_url 假服务）——验证请求形、key 不落日志、错误映射。
3. **集成层**：真实 `dsh-session` 持久化语义 + host apply → RPC 注册；RPC handler 用构造请求对象直调断言响应形。
4. **client 垫片**：Node 垫片执行构建产物 bundle，断言 ModuleLoader 接线 + 席位注册 id 正确（GUI 级验证本机不可行，环境坑 #1）。

## 基准脚本（发布证据，零 API 依赖）

- `bench:pipeline`：20 条内置草稿样例（`data/fixtures/drafts/`：中/英、口语化/歧义/超长/含特殊字符反引号+${}/含 /name 引用记号/空与过短边界），走"校验→渲染→桩模型→清洗"全管线，断言：错误码正确、清洗后输出 = golden 快照、特殊字符不破 script。
- golden 快照字节级冻结 → 依赖 `.gitattributes` `* text=auto eol=lf` + "快照出现 CR 即大声失败"守门测试（dsh-plugin-dev §10 EOL 坑）。
- 指标口径：管线断言通过率 100%（规则可判定项）；优化"质量"不自动评分，内置样例的人工评审记录留 `data/README.md` 台账（样例来源：自编 + 脱敏真实使用，注明许可）。
- "动了会打挂基准"的既定口径：golden 快照冻结、错误码语义、模板 id 清单、RPC 响应形——改动需重跑基准并在 HANDOFF 记录。

## data/ 台账

- `data/fixtures/drafts/`：草稿样例（生成器 + 手写），README 登记来源。
- `data/fixtures/model-responses/`：桩模型响应 fixtures（golden 输出）。
- 生成器（如需批量注入特殊字符用例）固定 seed 可复现。
