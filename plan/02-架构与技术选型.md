# 02-架构与技术选型

## 可行性核实结论（2026-09-29，包内容直读，dsh-pipeline 项目 node_modules 副本）

### composer 区域席位（证据：`@deepseek-ai/dsh-client-ui-conversation/lib/types/client/contract/slots.d.ts`）

| 席位 | kind | 用途 | 选用 |
|---|---|---|---|
| `conversation.input.right` | list | "Compact controls **before the composer submit action**"（提交动作前的紧凑控件） | ✅ 主席位：优化按钮（对标 WorkBuddy 模型选择器左侧位置，实际渲染顺序 M1 实机确认） |
| `conversation.input.left` | list | 工具行左侧紧凑控件 | 备选 |

| `conversation.composer` | chain | 整个 composer 接管 | ❌ 明确不用 |

### 草稿读写 API（证据：同包 `contract/input.d.ts`、`SessionStandardProps`）

- **读**：`useInput()` → `InputState { draft: string; draftRev: number; phase: 'plain'|'adjudicating'|'claimed'|'submitting'; occurrences: Occurrence[]; ... }`。`draft` 是编辑器文档的剪贴板投影（chips 展开为 `/name` 文本），`draftRev` 单调递增修订号。
- **写**：`inputActions.setDraft(text)` —— 注释明示 "Replace the whole draft (persisted-draft seed **and programmatic writes**)"；另有 `captureInsertion(): TokenSpan` + `insertText(text, span): boolean`（修订守卫的插入，span 里带 draftRev CAS）。
- 这两个都在 **SessionStandardProps** 上：任何 session 作用域的 slot 组件 props 直接可取——不需要碰 package-internal 的 `ComposerKeyboard`/`SessionInput`（注释明示那些不跨插件边界）。

### 会话内其他机制

- scope 为 `'session'` 的席位组件自动获得 `useInput`/`inputActions`/locale 等 standard kit（`dsh-client-ui-slots` 的 SessionStandardProps 五类 props 共享机制）。
- React 可用：冻结种子表含 react（dsh-plugin-dev §5）；client tsconfig NodeNext + lib ESNext。

## 总体架构

```
┌─ dsh 桌面端 (web profile) ──────────────────────────────────────────┐
│  host 半 (Node, apply(ctx))                client 半 (浏览器 bundle)   │
│  ┌──────────────────────────┐   RPC       ┌──────────────────────┐  │
│  │ POST /api/prompt-polisher│◄───────────│ composer.input.right │  │
│  │   /optimize              │  fetch+cookie│  优化按钮组件:        │  │
│  │  ├ 校验: draft 非空/长度  │───────────►│   useInput 读 draft   │  │
│  │  ├ 模型通路分派:          │  {optimized,│   inputActions.       │  │
│  │  │  a) workflow agent()  │   meta}     │   setDraft(optimized) │  │
│  │  │  b) 独立 API (M3)     │             │   状态: loading/err/  │  │
│  │  └ 模板渲染 + 输出清洗    │             │   还原原文            │  │
│  └──────────────────────────┘             └──────────────────────┘  │
└─────────────────────────────────────────────────────────────────────┘
```

### 模型通路 A（M2，默认）：workflow 引擎

- host 半 `ctx.workflowEngine.start({ script, meta, ... })`，script = 单 `agent()` 调用：把渲染后的优化模板发给当前会话模型，拿回文本。
- 依赖 cordis.patch.yml 翻转 `workflow-ptc` 的 `disabled: true → false`（web profile 默认禁用引擎；dsh-plugin-dev §3）。兼容 floor ≥0.2.0-rc.1。
- 成本：一次子代理运行；meta 强校验（name/description 非空）。

### 模型通路 B（M3）：独立 API 直连

- host 半用 Node fetch 调 OpenAI 兼容 `/chat/completions`（DeepSeek 官方 API 兼容），base_url/key/model 由用户配置；key 存宿主侧配置，绝不下发浏览器。
- 配置持久化通路 M3 落地时调研宿主 config 机制；fallback：插件自己经 host fs 存 profile 内数据文件。

### 输出清洗（防模型幻觉污染输入框）

- 要求模型"只输出优化后的提示词原文，不要解释/包裹代码块"；host 侧剥 markdown 围栏、去首尾引号、长度上限（如 8000 字符）校验；解析失败 → 返回错误，**绝不回填**。

## 关键风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R1 | `setDraft` 全量替换会**毁掉引用 chips**（@文件/@会话 chips 的 occurrence 信息丢失，/name 变纯文本） | 读 `InputState.occurrences`，非空时策略：默认按钮禁用+tooltip 说明"含引用，暂不支持优化"；二期尝试 insertText 拼接。进 M2 验收项 |
| R2 | `setDraft` 是否进 Lexical 撤销栈未证实，用户 Ctrl+Z 可能回不到原文 | 插件自存原文 + `conversation.composer.dock` 状态条（"已优化 · 还原"），还原不依赖编辑器 undo |
| R3 | `input.right` 实际渲染顺序/视觉与 WorkBuddy 有差 | M1 实机确认；备选 left/activity 席位，UI 上允许"位置近似" |
| R4 | 优化模型输出带解释/围栏污染草稿 | 输出清洗器 + 失败不回填（见上） |
| R5 | 引擎 script 注入：草稿文本含反引号/`${}` 破坏 script | 草稿文本不走 script 字面量拼接——经 `args` 传参进 agent() prompt，或 JSON 编码后解析（M2 定实现，测试覆盖特殊字符用例） |
| R6 | 优化请求与用户继续编辑竞态：用户点了按钮又打字 | `captureInsertion()` 的 draftRev CAS 或回填前重读 `useInput` 比对；草稿已变时提示而非静默覆盖（M2 定稿语义） |

## 技术选型

- dsh 目标版本：**0.2.0-rc.1**（next 线；与 dsh-pipeline 项目经验一致，workflow-ptc 引擎）。M1 实机 `dsh --version` 复核用户桌面端版本，若在 0.1.x 线则降级选型（引擎包名不同）再定 floor。
- 构建：esbuild cjs bundle + `window.__ModuleLoader__.load` banner/footer（照抄官方 dsh-client-ui-* 格式）；构建后 require 白名单扫描门。
- 依赖纪律：`@deepseek-ai/*` 精确 pin；浏览器依赖三处同步（external + 种子表 + ambient.d.ts）。
- 测试：node:test 离线三层（mock 引擎孪生 → 真实引擎+桩服务 → 真实 session 集成）；模型 API 不进 CI。
- 语言：TypeScript 全量；lint/test/bench 三命令门槛（ALL GREEN 才算过）。
