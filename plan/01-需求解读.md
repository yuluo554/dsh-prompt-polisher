# 01-需求解读

## 痛点 → 能力转译

| 用户痛点 | 能力 |
|---|---|
| 想到什么写什么，提示词口语化、有歧义，模型答偏 | 一键把草稿改写成清晰、完整、无歧义的提示词 |
| 自己写结构化提示词（角色/约束/输出格式）太费劲 | 内置风格模板，一键套用改写 |
| WorkBuddy 有这功能但 dsh 没有 | dsh composer 工具行图标按钮，同等交互位 |
| 怕优化"抢走"输入框控制权 | 优化结果仅回填草稿，用户随时可改；一键还原原文 |
| 不想被自动改写打断输入 | 仅手动按钮触发（用户拍板，不做自动防抖） |

## 已拍板决策（2026-09-29）

1. **触发方式：仅按钮**。输入框工具行图标按钮（对标 WorkBuddy 位置：模型选择器左侧），点击才优化。不做输入停顿自动优化。
2. **模型来源：两者都支持**。默认复用 dsh 会话模型（workflow 引擎 agent()，零配置）；设置里可切"独立 API"（OpenAI 兼容 base_url + key + model 直连）。M2 先做会话模型，M3 补独立 API。
3. **优化风格：多风格可切换**。预设"精炼明确 / 结构化增强"起步，模板可自定义（M3）。
4. **发布范围：发布上架**。npm 发包 + GitHub 开源 + awesome-dsh 渠道。
5. **UI：参考 WorkBuddy，图标自绘**。不复用其魔法棒图形。

## 边界与非目标（防 scope 失控）

- **不做**输入自动监听优化（用户明确排除）。
- **不做**消息发送拦截/改写已发送消息——只作用于未发送草稿。
- **不做**优化历史管理/云端同步（一期只保留"最近一次原文"用于还原）。
- **不做**独立聊天面板——优化就在当前输入框内完成。
- **不做**流式回填（一次返回整段文本；流式与 setDraft 全量替换语义冲突，收益低）。
- **不承诺**优化质量自动评分——质量靠模板设计 + 内置样例基准 + 人工评审（见 04）。
- 官方能力边界：不碰官方 composer 接管（`conversation.composer` chain）、不替换官方节点渲染。
