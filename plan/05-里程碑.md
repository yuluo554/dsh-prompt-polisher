## M1 骨架与点亮（首个可演示）

- npm 包三件套落地（patch insert 行 + host apply + client bundle）；包形按 03 §3.1。
- client：按钮组件注册 `conversation.input.right`（自绘临时图标即可），读 useInput，点击 POST `/api/prompt-polisher/optimize`。
- host：RPC 返回确定性伪优化（echo + 前缀标记），不接模型；校验与错误码骨架就位。
- 验证门：`pnpm lint && pnpm test` 绿；`dsh --profile web --dump-config | grep prompt-polisher` 插件行在；后台启动日志 0 条 "did not activate"；curl 带 cookie 调 RPC 通；Node 垫片执行 client bundle 断言接线；**实机目检**：按钮出现在输入框工具行，点击后草稿被替换（echo）。
- 决策点：实机确认 input.right 渲染位置与 WorkBuddy 近似度，不行就切备选席位。

## M2 真实优化 MVP

- workflow 引擎通路（patch 翻转 + 兼容 floor ≥0.2.0-rc.1 + args 注入）；默认风格 concise；输出清洗器。
- 按钮 loading/错误/禁用态；还原状态条（composer.dock）；竞态提示（R6）；chips 保护（R1）；空草稿禁用（FR5）。
- 测试：三层测试 + 桩引擎管线基准雏形（≥10 用例）。
- 验证门：实机全流程演示（烂提示词→优化回填→继续编辑→还原）；测试全绿；特殊字符 fixtures 过。

## M3 风格与独立 API

- 风格菜单（structured 预设 + 默认风格记忆）；自定义模板通路（FR10 最简形：配置覆盖）。
- 独立 API 通路：配置 UI（M3 调研宿主 config/设置页席位后定形）+ 连通性测试按钮 + key 不下发浏览器；通路降级（API 未配/失败 → 提示，可手动切回会话模型）。
- 验证门：切风格结果不同且各自 golden 快照过；配 DeepSeek 兼容 key 实机走通直连（用户协助验一次）；测试全绿。
