# data/ — 基准 fixtures 与 golden 快照（plan/04 台账）

本目录是发布证据的冻结资产：`test/bench.test.js` 驱动 `data/fixtures/manifest.json`
里的 20 个用例走真实优化管线（校验 → 渲染 → 桩模型 → 清洗），响应与
`data/golden/*.json` 做**字节级比对**。目录内所有文件均为 LF（`.gitattributes`
冻结 + EOL 守门测试大声失败）。

## 目录

| 路径 | 内容 | 来源 |
|---|---|---|
| `fixtures/manifest.json` | 20 用例清单（id / 草稿 / 风格 / 桩模型响应 / 期望） | `scripts/seed-fixtures.mjs` 生成 |
| `fixtures/drafts/` | 18 份草稿样例（另 2 例为清单内计算生成：近上限 7050 字、超上限 8001 字） | 手写自编，见下 |
| `fixtures/model-responses/` | 12 份桩模型响应（另 3 例为清单内计算/内联：空白输出、超长输出、原始空白串） | 手写自编，见下 |
| `golden/` | 每用例一份的期望响应（`optimize()` 返回值的完整 JSON，字节冻结） | `scripts/update-golden.mjs` 从真实管线生成 |

## 来源与许可（台账）

- **全部样例为 2026-09-30 M4 自编**（编写时参考 plan/01 场景清单），不含任何真实
  用户数据、真实人名、真实项目名；`/project-alpha`、`@张三` 为虚构记号（用于钉住
  引用记号原样保留的契约）。
- 无外部数据集、无爬取内容，许可 = 本仓库许可（MIT）。
- 后续如补充脱敏真实使用样例：必须走 plan/06 脱敏四步审查并在此登记来源与许可。

## 人工评审记录（plan/04 口径：优化"质量"不自动评分）

- 指标口径：管线断言通过率 100%（错误码、清洗、字节冻结全部规则可判定）。
- golden 中的"优化输出"是桩模型的罐头答案，代表**合理改写形态**，不作为质量基准；
  真实质量由用户日常使用主观评审（M3 目检已确认 concise/structured 两风格差异可辨）。
- 评审记录：2026-09-30 自编写入；待用户使用反馈后在此追加记录。

## 冻结纪律（动了会打挂基准的既定口径）

1. golden 快照**字节冻结**：改错误码语义、清洗器、模板输出、RPC 响应形后必须
   `node scripts/update-golden.mjs` 重生成，并在 HANDOFF + plan/06 记录变更原因。
   与任何已记录变更都对不上的 diff = 回归，先修代码不改快照。
2. fixtures 由 `scripts/seed-fixtures.mjs` 生成（固定 seed = 字面量表），可重复执行、
   字节稳定；改样例 = 改生成器再重播种 + 重生成 golden。
3. 任何文件出现 CR 即失败（EOL 守门测试）；不要用会写 CRLF 的编辑器保存本目录。

## 覆盖面（20 用例 = plan/04 要求的分布）

中/英（01/03/04/09）、口语化（01）、歧义（10）、超长近上限（11，7050 字）与超上限
（19，8001 字）、特殊字符反引号+`${}`+引号+换行+emoji（07）、`/name` 与 `@` 引用记号
原样保留（08）、空与边界（17 空白草稿 / 20 输出截断至上限）、封闭错误码全样本
（12/13 PARSE_FAILED、14/16 UPSTREAM_FAILED、15 CANCELLED、17 EMPTY_DRAFT、
18 BAD_STYLE、19 TOO_LONG）、默认风格缺省契约（01 不带 style）、FR10 模板覆盖走
router 形通路（10）。
