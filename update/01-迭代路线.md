## 四条方法论提醒（来自实测）

1. **「读了代码知道」≠「验证过」**。我直读了 0.2.1 的 5 类运行时契约（席位 / patch 行 id /
   configForms / locale）全部未变，也用 semver 复算了 dsh 的判据 —— 但**没有在 0.2.1 上装起来跑**。
   批次 2 的存在就是因为这个区别。
2. **`dsh.compatibility` 字段是装饰性的**。全树 grep 0 命中。真正决定插件能否加载的是
   `peerDependencies` 里 `@deepseek-ai/dsh-*` 的 range —— 改兼容性要改那里，不是改 `dsh.compatibility`。
3. **dsh 的 semver 校验带 `includePrerelease: true`**。凭直觉判断「预发布不被 range 覆盖」
   会得出错误结论（实际 `^0.2.0-rc.1` 能覆盖 `0.2.1-rc.2`）。
4. **验装唯一可靠方式 = 后台启动 + 读启动日志**；`npm publish` 必须显式 `--registry`（本机 `.npmrc`
   指向只读的 npmmirror）。这两条都是仓库自己踩过的坑（plan/06、dsh-plugin-dev skill §10）。
