二、核心问题（已由源码直读 + semver 实测确认，不要重新论证，直接修）
=========================================================
【问题】package.json 的 peerDependencies 里 5 个 @deepseek-ai/dsh-* 全是**精确版本 0.2.0-rc.1**。
dsh 的兼容性校验会因此判定：本插件在 dsh 0.2.1 上**不兼容 → 直接抛错拒绝加载**。

【dsh 的校验机制】（@deepseek-ai/dsh-app-boot/lib/index.js 的 evaluatePluginCompatibility()，源码实证）：
  1. 只校验 peerDependencies 中名字为 "@deepseek-ai/dsh" 或以 "@deepseek-ai/dsh-" 开头的项；
  2. 判据 = semver.satisfies(runtimeVersion, range, { includePrerelease: true })；
  3. 不兼容时：if (issue !== void 0 && !issue.exempted) throw new Error(pluginCompatibilityWarning(issue))
     —— 是**抛错拒绝加载**，不是警告；
  4. 补救只能靠用户手工 `dsh plugin allow-version`（精确 包名@版本 + 精确 dsh 版本）。

【package.json 的 dsh.compatibility 字段是装饰性的】
  在 @deepseek-ai/ 全树 grep manifest.compatibility / dsh.compatibility → **0 命中**。dsh 从不读它。
  所以 README 里「要求 dsh >=0.2.0-rc.1」这句话在 0.2.1 上得不到兑现 —— 真实门槛由 peerDeps 决定。

【实测：当前写法在各运行时下的兼容性】
  runtimeVersion='0.2.1-rc.2'，dsh 判据：
    @deepseek-ai/dsh-brand                    = 0.2.0-rc.1  → ✗ 不兼容
    @deepseek-ai/dsh-client-connection        = 0.2.0-rc.1  → ✗ 不兼容
    @deepseek-ai/dsh-client-ui-plugin-manager = 0.2.0-rc.1  → ✗ 不兼容
    @deepseek-ai/dsh-client-ui-settings       = 0.2.0-rc.1  → ✗ 不兼容
    @deepseek-ai/dsh-credentials              = 0.2.0-rc.1  → ✗ 不兼容
    @deepseek-ai/cordis                       = 4.0.4        → 不参与校验（名字非 dsh-*）
